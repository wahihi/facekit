## 남은 일

1. **나머지 2방향 미검증** — `portraitDown`, `landscapeLeft`. 아직 실기기
   테스트 없음. 오버레이 박스가 실제 얼굴과 정확히 겹치는지(육안)도 이
   두 방향에서는 확인 안 됨. `[_cameraQuarterTurns]` 디버그 로그의
   `turns` 값이 방향별로 기대한 대로 바뀌는지도 같이 확인.

2. **`_framingHint` 실사용 확인** — 줌이 최대인데도 얼굴이 작을 때 뜨는
   안내 문구("카메라에 조금 더 가까이 와주세요")가 실제로 뜬 사례가
   아직 로그에 없음. 최대 줌으로도 부족할 만큼 멀리 있어보는 테스트 필요.

3. **라이브니스 재활성화** — `example/lib/main.dart`의
   `_kLivenessEnabled = false`는 인식 안정성만 따로 검증하려고 넣은
   임시 디버깅 플래그. 인식 안정성이 이제 충분히 확인됐으니:
   - `true`로 되돌리고 통합 테스트(줌 + 방향 + 라이브니스 + 인식 전부
     켜진 상태)
   - `face lost` 500ms 유예시간이 여전히 너무 자주 리셋을 유발하는지
     별도 재측정 (지금까지 라이브니스 꺼놓고 테스트해서 이 부분 검증
     공백 상태)

4. **(우선순위 낮음) 세로로 긴 프레임에서 가운데 크롭 수직 중심 미세조정**
   — 가로 파지 시 `FaceImage`가 480×720(세로로 긴 모양)이 되는데, 가운데
   크롭이 수직 중심을 못 맞춰서 fallback이 자주 걸림(적중률 32.7%). 지금은
   fallback이 잘 메꿔주고 있어서 급하지 않음 — 필요해지면 크롭 중심을
   살짝 위로 옮기는 정도로 조정.

5. **(미해결, 참고용) 리파인먼트 fallback의 정확한 메커니즘은 직접 증명
   안 됨** — "부정확한 1차 bbox → 크롭이 실제로 얼굴을 빗나감"이라는
   가설은 결과 개선으로 간접 확인됐을 뿐, 크롭 좌표 vs 실제 얼굴 위치를
   직접 비교해서 증명한 적은 없음. 로그에 크롭 영역/1차 bbox는 이미
   남기고 있으니, 다음에 fallback이 다시 발생하면 좌표 비교 가능.
